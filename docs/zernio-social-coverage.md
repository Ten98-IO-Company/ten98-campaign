# Zernio social publishing and analytics coverage

Updated 19 October 2026 for the **v0.8.8 expansion**, against the official documentation and OpenAPI **1.292.0**. This records implemented subsets and remaining gaps. Automated and browser acceptance use isolated synthetic providers; no real accounts were connected, posts published, files uploaded, or billable searches made for this update. See [verification](verification.md) for run evidence.

The unreleased publishing subset includes YouTube keyword tags and accepted metadata requests, reviewed account defaults, Facebook Page event-access repair, TikTok/LinkedIn reports, exact-account Google Business location selection, Instagram quota/audio and TikTok music/location tools. Touched contracts use cached official OpenAPI **1.295.0**; this is not a fresh full-parity review. Native workflows remain app-owned on locally qualified `@ten98/ui` 0.3.15. The [current accepted checkpoint and visual gates](verification.md#current-accepted-checkpoint) are canonical; historical 931/0.3.14 and earlier acceptance receipts remain in verification. Article, product and collection workflows retain their [separate commerce bounds](zernio-commerce-admin-coverage.md), including contract-blocked Shopify published-content editing. Synthetic authorization previews establish no external consent or actual linking; live-provider acceptance and full parity remain unclaimed.

[Appearance instructions](../README.md) cover System, Light and Dark. Bounded preference reload/navigation/keyboard proof and native System behavior under OS light/dark emulation are accepted. Destination identity/readiness and positive-activity confirmation guards are included in the accepted automated candidate. Final bounded route/editor, authentication/access and narrow/keyboard evidence, with its synthetic-state limits, is recorded in [current verification](verification.md#current-accepted-checkpoint).

Understood as: expose Zernio's supported platform features as usable campaign-manager workflows, including selection, validation, results and recovery; a field accepted by a schema alone does not establish complete feature support.

**Implemented** means a bounded workflow has a server handler and usable UI. **Partial** means an existing workflow covers only part of the documented feature. **Missing** means no matching app workflow was found. **Unavailable** means the provider documentation expressly prevents normal use. These labels describe this app, not an independent guarantee from each platform.

The [platform catalogue](https://docs.zernio.com/platforms) and [documentation index](https://docs.zernio.com/llms.txt) were used for discovery; individual primary pages below substantiate the capabilities. Do not derive an implementation percentage from platform names or endpoint counts. Posting, messaging and blogs use different resource families. The catalogue and specification also use different headline platform counts, so this report enumerates the actual destinations instead.

## Resolved contract boundaries and remaining capability gaps

1. **Snapchat availability resolved in v0.8.5:** the [guide](https://docs.zernio.com/platforms/snapchat) denies new access globally. The [shared capability map](../shared/social-posts.ts) now marks it unavailable, and connection/publication/scheduling checks refuse it before dispatch. Browser acceptance saved a historic draft and verified rejected publication without an upstream write.
2. **Media bounds reconciled in v0.8.5:** the [shared definition](../shared/social-posts.ts) now enforces the [Instagram guide's](https://docs.zernio.com/platforms/instagram) 10-item carousel limit and [Facebook guide's](https://docs.zernio.com/platforms/facebook) 60-second Reel upper bound. Boundary regressions cover both. These checks do not establish live acceptance or codec/transcoding suitability.
3. **Slack removal:** the [Slack guide](https://docs.zernio.com/platforms/slack) describes unpublishing, but the [generic unpublish endpoint's enum](https://docs.zernio.com/posts/unpublish-post) omits Slack. The [app](../src/PostManagement.tsx) follows that enum. Obtain a current supported contract before adding a live-delete button; Discord uses its own message-delete endpoint.
4. **YouTube covers:** publishing, media-upload and metadata-update documentation describe different paths/constraints. Use the correct operation's limit and ownership checks; do not collapse all cover fields into one unverified URL control.
5. **Same-platform variants:** separate account captions/media/options and fixed times are implemented. Exact provider readback preserves unchanged approval intent and independent times; reviews show account copies. Repeated account/different-destination entries remain pending and ambiguous copy actions are blocked. Legacy replacement still requires confirmation when it would collapse different provider content.
6. **Current-schema coverage tests:** a test named “complete typed options” checks the app's own current rules and minimal examples; it is not an independent full-Zernio parity test. Validate against a reviewed external capability inventory and representative provider errors as well.

## Delivery and acceptance requirements

Extend the existing composer, account controls, calendar, report and recovery screens. Keep optional platform fields inside the chosen format's settings. Load destination/music/location choices only when needed. No generic raw API console should count as completion of these user flows.

| Delivery slice | Smallest complete acceptance check |
| --- | --- |
| Connection and capabilities | Connect/reconnect with denied permission, expired callback, revoked account and unavailable platform; confirm foreign-project accounts never appear or become writable. |
| Destination discovery | Select a real-shaped Page/organization/board/playlist/channel from a scoped fixture; changed defaults and removed destinations do not silently redirect a pending action. |
| Publishing parity | Distinct same-platform account captions/media/options; repeated destination IDs where supported; preview, validation, schedule, exact readback and approval snapshot all agree. |
| Queue/recycling/bulk | Timezone/DST and full-queue cases, concurrent enqueue, cancellation and row-level import failure; no duplicate posts after unreadable receipts. |
| Media | Large-file upload, progress/error/cancel, expired URL, metadata mismatch and failed provider processing; a Drive webpage never passes as delivered media. |
| Live edits and recovery | Text/metadata/thumbnail changes preserve media, unsupported platform actions are unavailable, and accepted writes followed by failed readback remain uncertain rather than retrying a new write. |
| Analytics | Distinguish zero, absent, stale, delayed, add-on denied and insufficient history; filter/scope/cursor restart tests; chart totals reconcile with actual response rows. |
| Platform utilities | Confirm permission/rate/billing failures, pagination and correct undo/readback; do not send messages or perform real engagement in ordinary automated acceptance. |
