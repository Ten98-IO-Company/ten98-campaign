# Short links, campaign QR codes and website tracking

Open **Links & tracking** inside a project. Give each link a name and a public HTTPS destination. An optional campaign association accepts either a campaign in the shared plan or a direct email, SMS or WhatsApp campaign in the same project. UTM parameters remain in the destination URL.

The app saves an immutable destination and a random, globally unique short code. Creating the same active destination and campaign again returns the existing link. Comparison uses the URL parser's normalized address; query parameter order remains significant. Rename or archive a link; create a new link to change its destination. Archived links return HTTP 410. Media delivery URLs are never rewritten. Social composers can shorten shared and platform-specific captions before saving. Save a direct campaign draft first, then shorten its plain text and save again; this keeps the links in its campaign report. URLs containing personalization fields such as `{{email}}` stay unchanged. Copy saved links into ad destinations, email HTML or approved WhatsApp template values where permitted.

Download the SVG QR code for print or digital creative. It encodes the saved short URL with `?source=qr`. The destination is the same as the ordinary short link. Domain changes apply to newly created links; existing links and printed QR codes keep their original domain.

## Use your own short domain

1. Choose a dedicated domain or subdomain, such as `go.example.com`, and point its DNS record at your existing reverse proxy.
2. Configure the proxy with a valid HTTPS certificate. Forward `/s/*` to this Ten98 instance, preserving the original `Host` header. Do not expose a separate redirect service or rewrite the short code.
3. An instance operator who is also a workspace owner or administrator saves `https://go.example.com` as the project's short-link origin. Use only the origin, without a path, query or fragment.
4. Open the displayed domain-check URL in a browser. It returns a read-only challenge from this instance when the domain and proxy route are configured correctly. The app never fetches an arbitrary hostname or reports DNS ownership as independently verified.
5. Create and test a link before printing its QR code. Keep old domains, certificates and proxy routes active for as long as their saved links need to work.

For an existing Nginx HTTPS server block, the relevant location is:

```nginx
location /s/ {
    proxy_pass http://127.0.0.1:3018;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-Proto https;
}
```

Provision DNS and TLS using your deployment's existing tools. This example does not provision a certificate. Keep `APP_URL` set to the main application origin; it does not change when you add a short domain. Redirects accept only the configured main application host or the saved link's branded host. They use a fixed saved destination, HTTP 302 and `Cache-Control: no-store`.

Only public HTTPS domain destinations are supported. Embedded credentials, literal IP addresses, private/local hostnames and redirects back into this app's short-link namespace are rejected. HTTP loopback is permitted only for the main application's local development origin, not for destination links.

## Add website or application tracking

A workspace owner or administrator allows the exact website origins that may submit events, for example `https://www.example.com`. HTTPS origins are required; the local application's HTTP loopback origin is also available for development. Subdomains and ports are distinct origins. An empty allowlist disables event intake.

Copy the script snippet shown in the project settings into the website:

```html
<script defer src="https://campaign.example.com/t/PROJECT_PUBLIC_TOKEN.js"></script>
```

The actual URL is generated by the app. Allow that script and its application origin in your website's Content Security Policy if applicable. Install one project's snippet per page. It records the initial pageview and path changes from `history.pushState`, `history.replaceState` and `popstate`; changing only the query or fragment does not produce another pageview. Record a named action with:

```javascript
window.ten98Track?.('lead_submitted');
```

Names must begin with a lowercase letter and contain only lowercase letters, digits or underscores, up to 64 characters. Do not put names, email addresses, order numbers or other personal information in event names or page paths. Custom properties and user identifiers are not accepted.

The script respects Do Not Track and Global Privacy Control. Event requests omit credentials and referrers. The app does not set tracking cookies, read session cookies, save IP addresses or user agents, create visitor fingerprints, or assign visitor identifiers. Query strings, fragments and referrers are not stored. Website paths themselves can still contain sensitive content, so choose application routes accordingly. Your reverse proxy and hosting access logs are controlled separately from these application aggregates.

The project token is public, not an authentication secret. Intake requires an exact allowed `Origin` and uses CORS without credentials. This stops unrelated browser origins from submitting; clients outside a browser can forge an Origin header. Treat these numbers as operational request counts rather than independently verified advertising conversions.

## Reports and limits

Reports show daily ordinary short-link visits, QR-tagged visits, pageviews and named events. Ordinary clicks and QR-tagged requests are separate counters; total visits is their sum. **These are requests and events, not unique people or proof that a human scanned a QR code.** Bots, repeated visits and manually added `source=qr` parameters can affect totals. HEAD requests and requests with `DNT: 1` or `Sec-GPC: 1` do not increase link counters.

Campaign filters apply to associated short links. Website events have no campaign identity and appear only in the whole-project report. Reports use UTC days and retain daily aggregates for 365 days; link totals cover the retained data. No person-level attribution or cross-site identity is inferred.

Per project, the app supports 1,000 saved links, ten allowed website origins, 600 event-intake requests per minute, 10,000 accepted event IDs per rolling 24 hours, and 2,000 distinct path/event combinations per UTC day. The instance caps website event-intake POSTs at 10,000 per minute; these intake limits do not cover redirect or script requests. Events have a maximum body size of 2 KiB. Duplicate UUIDv4 event IDs are ignored for 24 hours, then removed. Limits and expired data are cleaned during active requests; these bounded database counters are sized for a single installation. Use a dedicated analytics service if sustained traffic exceeds these limits.

## API

Authenticated project routes:

| Method | Route | Body or response |
| --- | --- | --- |
| GET / PUT | `/api/projects/:id/links/settings` | `{settings}`; PUT accepts `shortBaseUrl`, `allowedWebsiteOrigins` |
| GET / POST | `/api/projects/:id/links` | `{links}` / `{link}`; POST accepts `name`, `destination`, optional `campaignId` |
| PATCH | `/api/projects/:id/links/:linkId` | `{name?,archived?}` → `{link}` |
| GET | `/api/projects/:id/links/:linkId/qr.svg` | Authenticated `image/svg+xml` |
| GET | `/api/projects/:id/links/analytics?days=30&campaignId=...` | `daily`, `pages`, `events`, `links`, `totals`; 1–365 days |

Viewers can read links, QR codes and reports. Editors can create, rename and archive links. Settings require workspace administration; changing a short domain additionally requires instance-operator access.

Public routes are `GET /s/:code`, `GET /s/domain-check/:token`, `GET /t/:token.js`, and `OPTIONS` / `POST /api/tracking/:token/events`. Event bodies contain only `{eventId,name,path}`. The public endpoints do not authenticate through application sessions.

`campaignId` is the existing campaign's ID, with no channel prefix; IDs from either campaign collection are checked against the project. Deleting a campaign leaves its historical link association intact; its links and whole-project totals remain available. Event intake returns HTTP 204 for accepted, duplicate or privacy-excluded events, 400 for invalid fields, 403 for a disallowed origin, 413 for an oversized body and 429 for limits. Errors use `{error: "message"}`. A public token is not proof that an event happened.
