# Security

Do not publish credentials, user data, or exploit details in a public issue. Report suspected vulnerabilities through the repository’s GitHub private vulnerability reporting feature when available, or contact an organization maintainer privately.

For self-hosting, complete first-run account setup on loopback before public exposure, use an HTTPS reverse proxy, and protect the data volume and environment configuration. Use one application process with the current SQLite store. Public signup closes after setup; workspace invitations are bearer links, valid for seven days and single use. Share them only with their intended recipient. The app provides copyable links rather than sending email.

Only instance operators can configure shared provider credentials or run connection tests. Project mappings and provider-operation recovery also require workspace administration. Saved credentials use authenticated AES-256-GCM encryption with a key derived from the instance session secret. Back up the database together with the exact configured `SESSION_SECRET`, or the generated `data/session-secret`. Losing or replacing that secret makes saved integration settings unreadable. Encryption does not replace access controls on the running host or its backups.

Blank secret inputs keep existing values. Explicitly clearing a credential disables its environment fallback; resetting a provider restores server environment values. Google Drive and Calendar share the same service account. Settings saves do not make provider requests. Connection tests make explicit metadata/authentication reads, with no inference, publishing, messages, uploads, calendar changes, or bookings. Read access does not establish all write permissions.

The Google Maps API key is intentionally visible in the browser. Restrict it to Maps JavaScript API and the permitted HTTP referrers; never use a server secret in its place. Maps changes require a browser reload to apply its script policy and loaded credentials. Service-account private keys and other provider secrets are excluded from settings responses.

Optional content approval binds decisions to post text, recipients, media, schedule, and referenced creative metadata. Changes invalidate approval. Review decisions record their actor and time; they do not publish automatically. Provider-operation reviews require checking the actual external outcome: an applied decision retains the duplicate-action block, while a not-applied decision allows only a fresh manual attempt. Preserve the original receipts when investigating uncertain spending or delivery.

Local password changes verify the current password and revoke prior sessions. The server-only `reset-password` CLI reads account details from standard input, accepts only local password accounts, and revokes all sessions for that account. Keep passwords out of command arguments and shell history. Use the identity provider's MFA and recovery controls for OIDC accounts; invitation links do not replace existing passwords or automatically link identities by email.

The private database also contains message history, bounded webhook payloads, AI prompts/results, invitation hashes, approval snapshots, and operation receipts. Set suitable retention and backup access policies. Direct-message media links can expire; credentials and private media should not be placed in public delivery URLs. AI prompts and explicitly requested project context are sent to the configured OpenRouter model provider; inbox snippets require a per-request opt-in.

Zernio, Google, Broadsign, and OpenRouter are independently operated external services. Their access permissions, charges, availability, and terms apply to your configured accounts. The MIT license covers this application’s source code, not those services.
